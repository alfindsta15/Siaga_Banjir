Cara mengonlinekan
Hubungkan hardware ke software.

 
A. Demo dengan hotspot HP
  1. Hidupkan hotspot HP pada band 2,4 GHz, nama dan kata sandi sederhana, matikan hemat daya hotspot.
  2. Sambungkan komputer server ke hotspot yang sama, lalu cari IP komputer (ipconfig di Windows, ip a di Linux/Mac).
  3. Izinkan port 3001 di firewall.
  4. Isi SERVER_URL "http://IP-KOMPUTER:3001", Wi-Fi, dan kunci alat di alat, lalu unggah.
  5. Tunggu: status "Alat terhubung" di kotak kiri menjadi hijau dalam satu menit.

 
B. Online publik (VPS atau Cloudflare Tunnel)
  1. Cloudflare Tunnel: cloudflared tunnel --url http://localhost:3001 memberi alamat https sementara (berubah tiap dijalankan; untuk tetap, buat tunnel bernama).
  2. VPS: pasang Node.js 18+, jalankan server sebagai layanan, pasang HTTPS (misalnya Caddy), dan jalankan dengan TRUST_PROXY=1.
  3. Isi SERVER_URL "https://alamat-anda" di alat. Jangan membuka port 3001 langsung ke internet.

 
C. Di lokasi sungai (MiFi/router 4G atau Wi-Fi desa)
  • Sambungkan alat ke Wi-Fi MiFi/router 4G; server harus di alamat publik (cara B).
  • HTTPS memakai kuota lebih besar daripada HTTP.
  • Tanpa internet, WhatsApp tidak terkirim, tetapi lampu dan sirine lokal tetap bekerja.

 
D. Webhook WhatsApp (STATUS dan TANYA)
  
Bila memakai Baileys, webhook tidak diperlukan sama sekali (pesan grup diterima langsung oleh server). Bagian ini hanya untuk Fonnte. Webhook adalah alamat server ini yang dipanggil Fonnte setiap ada pesan masuk ke nomor Fonnte Anda. Tanpa webhook, pesan keluar (peringatan, laporan harian) tetap jalan; yang tidak jalan hanya balasan STATUS dan TANYA.

  
  1. Server harus bisa dijangkau dari internet lewat HTTPS. Alamat localhost atau IP lokal (192.168.x.x) tidak bisa dijangkau Fonnte. Pakai Cloudflare Tunnel atau VPS (panduan B).
    2. 
  
  2. Pasang kunci webhook di server saat menjalankan: WEBHOOK_KEY=rahasia123 node server/server.js (PowerShell: $env:WEBHOOK_KEY="rahasia123"; node server/server.js). Pilih kata acak yang panjang, bukan "rahasia123". Setelah itu kartu "Webhook STATUS/TANYA" di Status sambungan menjadi hijau.
    3. 
  
  3. Isi URL ini di Fonnte (fonnte.com > Device > pilih perangkat > pengaturan perangkat, kolom Webhook; letak menu bisa berubah, dan bila kolomnya tidak ada cek paket Fonnte Anda):

  

  
  1. Uji: ketik STATUS di grup warga. Bot harus membalas dalam beberapa detik. Lihat tab Ringkasan > Catatan kejadian: baris bertipe Webhook berarti pesan sampai ke server.

  
Tidak ada baris Webhook: Fonnte tidak menjangkau server (alamat bukan HTTPS publik, tunnel mati, atau URL salah). "key salah": bagian ?key= berbeda dengan WEBHOOK_KEY di server. Baris ada tapi tidak dibalas: ID grup di tab Notifikasi belum sama dengan grup tempat Anda mengetik. Bila daftar grup kosong, ID grup yang mengetik STATUS otomatis tampil di daftar grup (bertanda webhook).

 
F. Hardware dan software saling terhubung (dua arah)
  
Arah 1: hardware → software (alat mengirim data). Alat yang memulai. Tiap interval ia mengirim POST /api/device/telemetry berisi jarak sensor, dengan header X-Device-Key.

  
  1. Alat harus terhubung ke Wi-Fi 2,4 GHz yang punya internet (atau satu jaringan dengan server bila demo).
  2. Di config.h/.ino: SERVER_URL berisi alamat server persis seperti yang dipakai membuka dashboard ini (tanpa garis miring di akhir), dan DEVICE_KEY sama dengan kunci alat (tab Keamanan).
  3. Unggah, buka Serial Monitor 115200: harus muncul HTTP 200. Di dashboard, "Alat terhubung" hijau dalam satu menit.

  
Arah 2: software → hardware (server memerintah alat). Server tidak bisa menghubungi alat langsung, karena alat ada di belakang router/hotspot. Jadi perintah dititipkan di balasan setiap kiriman alat:

  
  • Ambang, jarak dasar, interval: ubah di tab Kalibrasi lalu Simpan. Alat menerima angka baru pada kiriman berikutnya (paling lama satu interval: 5 detik maket, 60 detik sungai) dan menyimpannya.
  • Pompa maket: di Ringkasan, Isi sampai target (pompa berhenti sendiri di tinggi itu; wadah dikosongkan dengan tangan setelah demo) atau Nyalakan/Matikan manual. Lewat MQTT perintah sampai seketika; lewat HTTP alat membacanya pada kiriman berikutnya. Nyalakan manual kedaluwarsa setelah 120 detik, dan alat punya pengaman sendiri.
  • Online lewat MQTT: isi MQTT_URL, MQTT_USER, MQTT_PASS di server dan PAKAI_MQTT 1 di alat; kartu "MQTT (broker)" di Status sambungan harus hijau. Panduan: TUTORIAL.md.
  • Bila alat offline, perintah tidak sampai. Alat tetap memakai angka terakhir yang tersimpan dan tetap menyalakan LED/sirine lokal.

  
Jadi "mengonlinekan" cukup satu hal: pastikan alat bisa menembak alamat server (arah 1). Arah 2 otomatis ikut berjalan lewat jalur yang sama.

 
G. Alat dan server online bersamaan, otomatis saat listrik hidup
    
  
  1. Server di tempat yang hidup terus: mini-PC, STB Armbian atau Raspberry Pi di balai desa, atau VPS murah. Laptop hanya untuk demo.
    2. 
  
  2. Jalan otomatis saat menyala: Linux pakai layanan systemd (contoh deploy/siaga-banjir.service); Windows pakai Task Scheduler "At startup" atau pm2. Dengan ini server hidup sendiri setelah mati lampu.
    3. 
  
  3. Online tanpa membuka port: Cloudflare Tunnel bernama yang dipasang sebagai layanan (alamat tetap), atau Caddy di VPS. Isi SERVER_URL di alat dengan alamat itu.
    4. 
  
  4. Urutan menyalakan tidak penting: alat mencoba menyambung ulang Wi-Fi tiap 10-15 detik dan mengirim ulang tiap interval, jadi boleh menyalakan alat atau server lebih dulu.
    5. 
  
  5. Cek bersamaan: kartu Status sambungan di atas hijau semua (Server hidup, Alat terhubung, WhatsApp, Folder data). Bila "Sudah berjalan" selalu kembali ke nol, server mati-hidup sendiri.
    6. 
  
  6. Listrik: alat, router/hotspot, dan komputer server perlu cadangan daya (UPS atau power bank) agar tetap online saat banjir. Tanpa internet, LED dan sirine lokal tetap bekerja.
Langkah lengkap dan contoh berkas ada di docs/ONLINE.md.

 
E. Bila alat tidak terhubung
  • HTTP -1: alat tidak menjangkau server (Wi-Fi 5 GHz, SERVER_URL salah, firewall, isolasi klien hotspot).
  • HTTP 401: kunci alat berbeda dengan di server.
  • Sering putus: hotspot mati sendiri, sinyal lemah, daya kurang (tambah kapasitor).
  • Sensor tidak membaca: periksa kabel, catu, dan jarak minimal.
